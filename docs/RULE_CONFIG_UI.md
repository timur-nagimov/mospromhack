# Настройка правил в редакторе камер

Форма читает `params_schema` и необязательный `zone_schema` из `GET /api/rules/types`. Списка специальных типов правил в редакторе нет. Конфигурация камер не сохраняется автоматически.

Числовая матрица 2×2, объявленная схемой как две точки, отображается четырьмя управляемыми полями: X/Y первой и второй точки. Границы, целочисленность и обязательность приходят из схемы; для текущего направления координаты ограничены диапазоном 0..1. Если направления ещё нет, поля остаются пустыми: интерфейс не придумывает стрелку. Семантические ограничения конкретного правила дополнительно проверяет backend.

Валидация читает текущий черновик синхронно при отрисовке формы и кнопки «Сохранить». Проверяются обязательные значения, конечность чисел, включительные/исключительные границы, целочисленность, строки, enum, размеры массивов, вложенные элементы и запрещённые дополнительные параметры. Пустые обязательные `capacity` и `dwell_s` показывают ошибку и блокируют сохранение, даже если правило выключено или вкладка «Правила» закрыта. Пока описание существующего типа не загружено, сохранение также недоступно.

Отсутствующие необязательные параметры показывают schema defaults, соответствующие backend (включая логические `true`). Явно очищенное числовое поле остаётся пустым невалидным черновиком и не подменяется default. Для общих времён правила проверяются конечность и неотрицательность, для доли кадров — диапазон 0..1; дополнительных верхних пределов UI не вводит.

Общий JSON-редактор остаётся для других структур. При ошибке JSON введённый текст хранится как явный невалидный черновик; старое корректное значение не отправляется вместо него. Ошибка видна рядом с полем и блокирует сохранение. «Отменить» возвращает последнюю загруженную версию. Перезапрос сохраняет несохранённый ввод, обновляя базовую версию для отмены; чистая форма сразу получает новые значения.

`zone_schema` задаёт допустимое число выбранных зон. При `minItems=maxItems=1` нужно явно выбрать одну существующую зону; «Весь кадр» отсутствует, выбор другой зоны заменяет предыдущую. Удаление зоны, после которого связанное правило нарушит schema, блокируется с сообщением: сначала переназначьте зону или удалите правило. Выключение строгого правила не отменяет его контракт. Правила без `zone_schema` сохраняют прежний выбор всего кадра/нескольких зон; при удалении их последней явно выбранной зоны правило выключается, чтобы не расширять его действие молча.

Неверная конфигурация не отправляется в API. Backend остаётся окончательным валидатором семантики правила и отвечает за атомарное применение; UI показывает его ошибку при отклонённом сохранении.

Проверки без установки новых зависимостей:

```bash
node frontend/node_modules/typescript/bin/tsc --noEmit -p frontend/tsconfig.json
tools/heavy.sh node --test frontend/scripts/test-rule-config-ui.mjs
```

Rendered tests используют реальные React-компоненты, временный Vite-сервер без `.env`, подменённые HTTP-ответы и отдельный временный профиль Chromium. По умолчанию Playwright использует свой стандартный установленный Chromium. Локальный совместимый браузер можно явно выбрать через `UI_BROWSER_PATH`, например для Yandex на macOS:

```bash
UI_BROWSER_PATH='/Applications/Yandex.app/Contents/MacOS/Yandex' tools/heavy.sh node --test frontend/scripts/test-rule-config-ui.mjs
```

Сервер, браузер и временные файлы закрываются после тестов. Production build запускается отдельно.
