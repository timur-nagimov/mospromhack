При объединении проверил следующие условия:

- Долговечная запись события предшествует уведомлению и сбору сэмпла маховика;
  повторные попытки не дублируют оповещение или планирование клипа.
- Смена capture сохраняет закрытие старого события до сброса трекеров и правил.
  Модельные ошибки и неизвестные наблюдения не превращаются в безопасный кадр.
- Динамические зависимости `vehicle_proximity.params.models` проверяются до
  записи конфигурации. При отсутствии модели погрузчика API отвечает 422.
- Gateway сохраняет лёгкий запуск без inference, источников видео и OpenCV.
  Метки оператора переносятся в маховик после записи события в SQLite.
- Остановка с живым consumer или writer не закрывает используемые SQLite.
  После завершения потока остановку можно повторить; ошибка запуска потока
  также корректно освобождает ресурсы.

## Границы результата

В реестре 13 типов правил. Новые `wrong_way`, `zone_dwell` и `zone_overcapacity`
остаются opt-in; их полевое качество не измерялось. Сохранил текущие production
модели и PPE `full_frame`: ROI и RF-DETR не дали достаточного основания для замены.
Последние локальные тесты не являются новой приёмкой внешнего LinQ или INT8.
Карточка CPU-кандидата forklift не подтверждает наличие TPU-программы.

Полноценные edge sender/assembler сэмплов маховика отсутствуют в исходной основной
ветке. Их не подменял локальным проигрыванием: ручной capture на gateway без
поддержанного источника возвращает штатный 503 вместо ошибки сервера.

Исторические отчёты сохраняют исходные метрики и hashes. Если рабочий файл
изменился, ссылка на захваченные bytes перенесена в отдельный локальный снимок;
текущий код не выдаётся за исходник старого эксперимента. Прогон TPU 12:34
помечен недостоверным из-за второго потребителя очереди, согласно уточнению
в [EDGE](EDGE.md#64-стабильность-10-минут-с-таймаутом-tpu-5-с).
Большие исторические сырые замеры сохранены локально в
`data/historical_validation_20261024/`; в основной ветке оставлены итоговые отчёты.
