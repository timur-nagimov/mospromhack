# Превышение числа наблюдаемых людей в зоне

`zone_overcapacity` проверяет настроенный предел в одной явно выбранной зоне.
Используется существующий `det` и его person tracker; новые веса не нужны.
Плагин не включается автоматически в конфигурации камер.

```json
{
  "rule_id": "capacity_work_area",
  "type": "zone_overcapacity",
  "zones": ["work_area"],
  "params": {"capacity": 3, "min_conf": 0.35, "min_box_h_px": 40, "min_track_hits": 3},
  "min_duration_s": 2,
  "min_ratio": 1,
  "close_after_s": 3
}
```

`capacity` — обязательное положительное целое; его задаёт политика объекта.
Считаются person tracks с `last_seen == ctx.ts`, достаточными confidence, высотой
рамки и числом наблюдений. Точка опоры должна находиться внутри активного
полигона. Один track ID учитывается один раз; почти одинаковые bbox с IoU≥0.98
консервативно объединяются. Другие зоны, устаревшие и некорректные треки исключены.

Это **оценка по наблюдаемым трекам**: детектор может пропустить человека или
разделить его на несколько треков. Дедупликация не гарантирует физически точное
число людей. Значение ниже предела не доказывает безопасность или полную
наблюдаемость площадки. Необходимы реальные видео с разметкой людей и счётчиков.

Правило использует [явный статус моделей](RULE_OBSERVATIONS.md). Отсутствующий
статус, unsupported и ошибка не считаются успешно обработанным пустым кадром.
Недопустимые/повторные timestamps не дают нового доказательства. При переходе
capture Worker создаёт новый экземпляр правила после durable closure.

Плагин выдаёт одно групповое нарушение на зону: `track_id=null`, bbox — границы
полигона. Details содержат наблюдаемый count, limit, IDs участников и подавленные
почти одинаковые рамки. Смена участников не меняет ключ инцидента. Подтверждение,
`min_duration_s`, `min_ratio`, закрытие и повторы выполняет существующий
EventManager; история решения оператора сохраняется через обычный Journal/outbox.
Закрытие отражает конец подтверждённых наблюдений, а не вывод «на площадке безопасно».

Model-free проверки покрывают N−1/N/N+1, дубли, свежесть, геометрию, расписание,
unknown/error, строгие параметры и реальную цепочку Tracker→Rule→EventManager→SQLite.
Они подтверждают реализацию условий, но не измеряют качество на реальных камерах
и не доказывают TPU-инференс. Плагин использует действующий inference backend.
