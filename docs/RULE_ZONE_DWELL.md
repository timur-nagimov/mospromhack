# `zone_dwell`: непрерывное наблюдаемое пребывание в зоне

Опциональное правило выдаёт нарушение, когда свежий трек человека непрерывно наблюдается внутри одной явно выбранной зоны не меньше `params.dwell_s` секунд. Правило регистрируется автоматически через существующий реестр плагинов. Камеры и правила по умолчанию не меняются.

Пример элемента `CameraConfig.rules` для уже существующей зоны `loading`:

```yaml
rule_id: loading-dwell
type: zone_dwell
enabled: true
zones: [loading]
params:
  dwell_s: 30
  max_gap_s: 1
  min_conf: 0.35
  min_box_h_px: 40
min_duration_s: 2
min_ratio: 0.7
close_after_s: 3
cooldown_s: 30
severity: high
```

| Параметр | Контракт |
| --- | --- |
| `zones` | Ровно один ID существующей зоны данной камеры. Не выбирается автоматически по `kind`. |
| `dwell_s` | Обязательное конечное число строго больше нуля. Порог включительный: `elapsed >= dwell_s`. |
| `max_gap_s` | Конечное число в `(0, 60]`, по умолчанию 1. Интервал между соседними наблюдениями больше этого значения начинает отсчёт заново. |
| `min_conf` | Конечное число в `[0, 1]`, по умолчанию 0.35. |
| `min_box_h_px` | Целое число не меньше нуля, по умолчанию 40 пикселей исходного кадра. |

Неизвестные параметры, отсутствующая/неоднозначная зона, вырожденный или ненормированный полигон и некорректное расписание отклоняются конструктором. JSON schema публикуется существующим `GET /api/rules/types` и объявляет `dwell_s` обязательным. Общий путь валидации camera CRUD должен проверять параметры до сохранения конфигурации; проверка одного описания schema сама по себе не исполняет эту валидацию.

## Что считается временем пребывания

Используется время захвата `FrameContext.ts`, а не время обработки или возраст трека. Даже давно существующий трек начинает новый отсчёт в первом подходящем наблюдении внутри зоны. Точка опоры — середина нижней стороны рамки. Действует существующая геометрия `point_in_zone`: граница полигона включена.

Для каждого наблюдения обязательны `model_observations["det"] == "observed"`, класс `person`, конечные confidence и координаты, рамка положительной площади внутри исходного кадра, достаточная высота и `track.last_seen == ctx.ts`. Полностью отсутствующий статус старого `FrameContext` считается `not_observable`. Плагин использует общий `RulePlugin.observation_status` и явно записывает результат в `ctx.rule_observations[rule_id]`.

Отсчёт для человека прерывают выход из зоны, отсутствие свежей подходящей рамки, низкая уверенность, stale-трек, повторный/неоднозначный ID и смена `first_seen` у повторно использованного ID. Вся непрерывность прерывается при неизвестном/недоступном/ошибочном наблюдении модели, невалидном, повторном или обратном времени, слишком большом интервале между кадрами и смене размера исходного кадра. Невалидное время/размер отмечается как `not_observable`. Следующий подходящий кадр начинает новый интервал с нуля; пропущенное время не добавляется.

Расписание выбранной зоны применяется к глобальному epoch захвата через существующий `Europe/Moscow` контракт. В неактивные часы время не накапливается. Пересечение полуночи и конец интервала обрабатываются общим `is_zone_active`; отдельного часового пояса или пространственного допуска у правила нет.

## Жизненный цикл события и границы источника

После достижения порога плагин выдаёт одно текущее нарушение на человека и зону. Затем обычный `EventManager` применяет `min_duration_s`, `min_ratio`, `close_after_s` и `cooldown_s`. Например, при `dwell_s=30` и `min_duration_s=2` первые 30 секунд доказывают пребывание, а подтверждение события требует ещё штатного окна подтверждения. `Event.started_at` — первый кадр нарушения после достижения dwell-порога; время первого наблюдения в зоне хранится отдельно в `details.observed_inside_since`.

В `details` также сохраняются наблюдаемая длительность `dwell_s`, настроенный предел `dwell_limit_s`, `max_gap_s`, зона, точка опоры и `evidence=fresh_observed_person_inside_zone`. Детали подтверждённого события являются сохранённым свидетельством; это не счётчик длительности, обновляемый каждый кадр.

Плагин не подтверждает, не закрывает и не переоткрывает события самостоятельно. Штатные Journal/Engine/outbox сохраняют ID, исходное время, origin, операторский статус/заметку и клип при reopen. Новая граница capture обрабатывается существующим CameraWorker: старые события долговечно закрываются на их последнем нарушении, затем пересоздаются трекеры и экземпляры правил и сбрасывается состояние менеджера этой камеры. Старый dwell не переносится в новый capture. Состояние плагина локально экземпляру и ограничено свежими подходящими треками текущего кадра; соседняя камера и другие выбранные зоны независимы.

## Проверка и ограничения

`tests/test_rules_zone_dwell.py` проверяет порог до/ровно/после, старый трек при входе, повторный вход, пропуски/ошибки, невалидные рамки и часы, расписание, две зоны/камеры и HTTP schema/CRUD. Интеграционные проверки используют настоящий CameraWorker → Tracker → Rule → EventManager → SQLite Journal с синтетическими детекциями; включены подтверждение, reopen, долговечный outbox, operator evidence и смена capture. Модели и внешние сервисы не запускаются.

Это доказательство непрерывности по дискретным наблюдениям, а не физическое измерение присутствия между кадрами. Краткий выход между кадрами, невыявленная смена человека при ошибке трекера или необъявленная смена источника могут остаться незамеченными. Нужны полевые данные для выбранных камер, зон, частоты кадров и окклюзий; синтетические тесты не оценивают качество детектора и трекера. Правило не оценивает личность, роль человека или допустимость длительного пребывания вне настроенной политики зоны.
