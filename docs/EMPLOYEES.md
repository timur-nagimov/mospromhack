# Сотрудники и персональная статистика

Справочник содержит всех добавленных сотрудников, включая сотрудников без инцидентов.
Это сотрудники предприятия, а не учётные записи для входа. Данные реального запуска
первоначально пусты; вымышленные люди автоматически не добавляются.

Автономный мок-интерфейс содержит десять вымышленных сотрудников с табельными номерами
`DEMO-001` — `DEMO-010`. Общий набор хранится в `frontend/src/domain/demoEmployees.json`.
Чтобы явно добавить их в локальную SQLite, используйте:

```bash
python -m tools.seed_demo_employees --db-path data/local-ui/guard.db
```

Повторный запуск не создаёт дубликаты и не перезаписывает сотрудников, уже имеющих
такие табельные номера. Остальные записи и назначения виновников сохраняются.

## Интерфейс

- «Сотрудники» доступны всем четырём ролям. Поиск работает по ФИО, табельному номеру,
  подразделению и должности. Список не ограничен первой страницей или наличием событий.
- Добавлять сотрудников может только администратор. ФИО обязательно; табельный номер,
  подразделение и должность необязательны. Непустой табельный номер уникален, одинаковые
  ФИО допустимы. У каждого сотрудника есть постоянный ID.
- В карточке события диспетчер смены (`operator`) и администратор выбирают нескольких
  виновников и нажимают «Сохранить виновников». Можно заменить или очистить весь список.
  Инженер по ОТ и сотрудник читают сохранённый список без редактирования.
- Выбор сотрудника в «Аналитике» фильтрует всю страницу: список, счётчики, графики по
  типам, участкам, камерам, дням и часам показывают только его подтверждённые нарушения
  за общий выбранный период. CSV использует тот же отбор. Очистка выбора возвращает
  общую аналитику. К персональному отчёту можно перейти из справочника.

Каждое назначенное событие учитывается у сотрудника один раз. Если виновников несколько,
оно входит в отчёт каждого из них после подтверждения. В персональную статистику и
CSV входят только события со статусом `confirmed`; новые, ложные и переданные мастеру
исключены. Назначение виновника само по себе не меняет статус события и не подтверждает
нарушение. Метрики точности и решений оператора остаются в общей аналитике.

CSV включает ФИО, табельный номер, подразделение, должность, ID и время события,
тип, статус, важность, камеру, участок, зону и комментарий оператора. Формат — UTF-8
с BOM, разделитель `;`, время по Москве, защита текстовых ячеек от формул Excel.
Выгрузка содержит все подтверждённые нарушения сотрудника за период, без лимита
общего журнального экспорта в 20 000 событий.

## API

Все новые маршруты требуют `X-Guard-Role: worker|operator|safety|admin`.
HTTP-клиент передаёт актуальный выбор переключателя перед каждым запросом.
**Это текущий демонстрационный режим выбора роли, не аутентификация пользователя.**
Сервер проверяет роль для операций ниже; полноценный вход и удостоверенные сессии
из общего контракта `ROLES.md` пока не реализованы.

| Метод и путь | Доступ | Ответ |
|---|---|---|
| `GET /api/employees` | Все роли | Полный массив сотрудников |
| `POST /api/employees` | admin | 201, сотрудник с ID и временем создания |
| `GET /api/events/{id}/employees` | Все роли | Сохранённый список виновников |
| `PUT /api/events/{id}/employees` | operator, admin | Полная замена, тело `{employee_ids: [...]}` |
| `GET /api/employees/{id}/report?from=&to=` | Все роли | Сотрудник, итоги, типы и все его подтверждённые нарушения |
| `GET /api/employees/{id}/report?format=csv&from=&to=` | Все роли | Полный CSV |
| `GET /api/analytics?employee_id=&from=&to=` | Аналитика | Все агрегаты только по подтверждённым нарушениям сотрудника |

Поля создания: `{full_name, personnel_number?, department?, position?}`. Строки
обрезаются по краям. Ошибки: 403 — роль не разрешена, 404 — нет сотрудника/события,
409 — занят табельный номер, 422 — неверные данные, повторяющиеся или неизвестные ID.
Границы периода — конечные epoch-секунды, включительно, по `confirmed_at`. Без границ
берётся вся история подтверждённых нарушений. Сотрудник без подтверждённых назначений
получает нулевой отчёт и CSV с заголовком.

## Хранение и проверка

`guard/employees.py` подключён к соединению и блокировке `Journal`. Таблицы `employees`
и `event_employees` добавляются в существующий файл `GUARD_DB_PATH` при открытии,
без удаления событий и изменения wire-контракта `Event`. Неверное назначение откатывается
целиком. Ручные связи сохраняются после завершения события, повторного открытия журнала,
репликации и replay на gateway; edge не перезаписывает их.

При раздельном edge/gateway справочник и назначения ведутся на gateway, где работает
оператор. Между независимыми gateway справочник автоматически не синхронизируется.
Мок-режим поддерживает тот же сценарий, но хранит сотрудников и связи в памяти вкладки.

Профильные проверки: `tests/test_employees_api.py` — права, валидация, атомарность,
пустые отчёты, статусы, полный список/выгрузка за пределами 1000 записей, перезапуск
и сохранность назначений при репликации.
