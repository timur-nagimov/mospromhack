## Рамочная оценка на Construction-PPE

Все три модели обработали **141/141 одинаковых test images без ошибок**.
Общий отпечаток image/label/YAML:
`800a03725b2c6fc37b8c80794735a03666fd424cc63b4eeecb54b548e37b6791`.
GT: 236 человек, 192 каски, 178 жилетов, 40 отсутствий каски; отсутствий
жилета в GT нет. Только официальный test split, без обучения или настройки.
Пересечение публичных изображений с обучением PPE-модели не проверено.

Единый production Detector, AP confidence 0.001, NMS IoU 0.7, рабочая
confidence 0.35, CPU ORT два потока. AP50 использует precision по 101 recall
точке; это не полный COCO mAP. Core — среднее person/helmet/vest с общим
знаменателем 3; unsupported классы с GT дают ноль.

| Модель | Person AP50 | Helmet AP50 | Vest AP50 | Core AP50 | Detector p50 / p95, мс |
|---|---:|---:|---:|---:|---:|
| COCO YOLOv8n | 0.757 | 0 (unsupported) | 0 (unsupported) | 0.252 | 60.99 / 65.62 |
| COCO YOLOv8s | 0.727 | 0 (unsupported) | 0 (unsupported) | 0.242 | 168.01 / 188.64 |
| BuildVision PPE v0.3 | 0.791 | 0.895 | 0.847 | 0.844 | 167.12 / 180.55 |

**Главное ограничение PPE-кандидата — отрицательные классы.** Для `no_helmet`
AP50 всего 0.136, precision 0.250, recall 0.200 в рабочей точке: корректно
сопоставлены 8 из 40 исходных GT-объектов. Дополнительный IoU 0.3 даёт AP 0.369 и recall
0.375; эта диагностика не заменяет основную AP50. Высокий core балл
положительных классов не доказывает качество тревог об отсутствии СИЗ.
`no_vest` не оценён из-за отсутствия GT, respirator модель не поддерживает.

Разбор всех 141 изображений дал 8 TP / 24 FP / 32 FN относительно исходных
меток. У 17 из 32 FN есть сохранённая рамка с достаточным IoU, но confidence
ниже 0.35; у 8 одновременно низкая confidence и недостаточный IoU; у 6 есть
рабочая рамка с недостаточным IoU; у 1 нет пересекающейся сохранённой
`no_helmet` рамки. Это разбор post-NMS outputs ≥0.001, не сырых anchor scores.
Из 24 FP 18 имеют ненулевой, но недостаточный IoU; 4 находятся на изображениях
без `no_helmet` GT и 2 не пересекаются с имеющимися GT. При IoU 0.3 семь
исходных FP становятся TP, но порог основного сравнения не изменяется.

Визуальные примеры показывают разные границы GT головы/лица и возможные
пропущенные метки. На `test/image1239.jpg` исходная no_helmet рамка находится
на торсе: официальный class ID 7, байты image/label совпадают с закреплённым
ZIP; расхождения размеров PIL/OpenCV и EXIF повороты исключены на всех 141
изображениях. Поэтому «FP» здесь означает несопоставление с исходным GT,
а не доказанную семантическую ошибку тревоги. Исходные метки не исправлялись.
В `data/model_research/ppe-error-audit/` сохранены `audit.json`, скрипт,
политика детерминированного выбора примеров и две контактные таблицы
`false-positives.png` / `false-negatives.png`. Таблицы иллюстрируют ошибки,
полная численная сводка охватывает весь набор. Нужны единые правила границ
рамки и надёжная разметка целевых кадров; снижать confidence на test нельзя.

Реальные PPE predictions дополнительно прошли production association и
мгновенное правило S2: 238 рамок person, 52 rule hits; в 29 изображениях
встречается unknown helmet. Это проверка семантического подключения на still
images с новыми track-объектами, без temporal EventManager и оценки качества
событий. При отсутствии наблюдения атрибут остаётся unknown, не False.

## Исправления и дальнейшая модельная работа

До сравнения исправлены настоящий дефект AP-интеграции (2 GT + 1 идеальный
TP прежде давали 0.75 вместо 51/101), коллизии имён изображений между split
и уменьшение core знаменателя у person-only моделей. Регрессии и формула —
[PPE_EVALUATION.md](PPE_EVALUATION.md). Метрики выше посчитаны исправленным
оценщиком. S1 evaluator не менялся.

Следующий приоритет — целевая разметка каска/без каски и жилет/без жилета,
включая закрытые головы, дальних людей, чистые случаи и unknown, затем
раздельные train/validation/test по площадке и камере. Сначала согласовать
head/face box definition и полноту отрицательных меток. Только после этого
имеет смысл fine-tuning отрицательных классов и подбор порогов на validation.
Для S1 нужны actor-aware интервалы и независимые чистые зоны; для S2 —
отдельная событийная оценка на видео с COCO-person треками конвейера.

Pose и fire ONNX в этой копии всё ещё не подготовлены. S3/S6/S8 требуют pose;
fire/smoke не является детектором курения. Эти пробелы не закрываются заменой
COCO n на s. TPU, обучение, целевые производственные видео и длительная
эксплуатационная оценка в этот пакет не входят.

Итоговая проверка snapshot `6772a0a`: **973 passed**, одно предупреждение
deprecated Starlette/httpx test client. Устранены два замечания P2
к comparator: завершение всей process group после выхода лидера и fingerprint
содержимого production Python-модулей до/после обоих прогонов. Эти изменения
проверены регрессиями без повторного heavy A/B; исходный runtime snapshot и
SHA каждого ранее выполненного прогона сохранены в отчёте. Frontend не менялся.
