# Контракт выбора зон для правил

`GET /api/rules/types` может возвращать необязательный `zone_schema` — JSON Schema
поля `RuleConfig.zones`. UI получает ограничения из метаданных плагина, без списка
особых типов правил в клиентском коде.

`zone_dwell`, `wrong_way` и `zone_overcapacity` объявляют:

```json
{"zone_schema": {"type": "array", "minItems": 1, "maxItems": 1}}
```

Для этих правил нужна ровно одна явно выбранная зона камеры. `null`, пустой массив
и несколько зон не соответствуют контракту, в том числе у отключённого правила.
Отключение правила само по себе не делает некорректную конфигурацию допустимой.
При удалении последней выбранной зоны редактор должен разрешить конфликт перед
сохранением: выбрать другую существующую зону либо удалить зависимое правило.

У `RulePlugin.zone_schema` по умолчанию значение `None`; в этом случае ключ
`zone_schema` отсутствует в ответе. Метаданные прежних десяти правил сохраняют
прежние поля и значения. Отсутствие схемы не задаёт новых ограничений и не
отменяет существующую семантику зон конкретного правила.

Это описание для редактора, а не новый механизм runtime-валидации. Конструкторы
трёх правил уже проверяют количество и существование выбранных зон; backend
вызывает их до сохранения конфигурации. Алгоритмы, параметры и пороги не меняются.
