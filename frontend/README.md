# Зазеркалье — веб-интерфейс

Пульт диспетчера охраны труда: мониторинг камер и лента тревог, карточка события с решением оператора, журнал, аналитика, настройка камер, зон и правил, производительность конвейера и ускорителя LinQ.

React 18, TypeScript, Vite 5, React Router (HashRouter), TanStack Query, Recharts. UI-китов нет: компоненты и стили свои. Шрифты Onest, Tektur и JetBrains Mono лежат в бандле (`@fontsource`), поэтому интерфейс работает офлайн.

## Node.js

Vite 5 требует Node 18 или новее, а в системе по умолчанию стоит Node 16 (nvm). Поэтому Node 20 поставлен через Homebrew без sudo:

```bash
brew install node@20                          # один раз
export PATH=/opt/homebrew/opt/node@20/bin:$PATH
node -v                                       # v20.x
```

Все команды ниже запускаются с этим `PATH`. Файл `.nvmrc` содержит `20`, так что с nvm хватит `nvm use`.

## Режимы запуска

Все команды выполняются из `frontend/`. Сначала `npm ci`.

| Режим | Команда | Откуда данные |
|---|---|---|
| dev + бэкенд | `npm run dev` → http://localhost:5173 | прокси Vite на `http://localhost:8000` (`/api`, `/ws`, `/health`) |
| dev + мок | `npm run dev:mock` или `VITE_MOCK=1 npm run dev` | генератор в браузере, бэкенд не нужен |
| prod | `npm run build` → `frontend/dist` | FastAPI раздаёт `dist` с `/`, API на том же origin |
| prod-мок | `npm run build:mock` → `frontend/dist-mock` | статическая демо-сборка без бэкенда |

Любую сборку можно перевести в мок-режим параметром адреса `?mock=1`, например `http://localhost:8000/?mock=1`. Это запасной вариант для демо, если бэкенд упал. Выбор запоминается в `localStorage`, вернуть обратно можно через `?mock=0`.

В мок-режиме:
- 6 камер с зонами и правилами (в том числе зона «Проход у стеллажей», активная 07:55–12:00, как в сценарии кейса);
- журнал за 30 дней, около 450 событий с решениями оператора;
- через 2,5 с после загрузки приходит критическое «Падение», дальше новое событие каждые 10–20 с через фейковый WS;
- метрики приходят раз в 2 с (бэкенд `linq-tpu`, задержки по этапам, загрузка ускорителя);
- видео — синтетическая «камера» на canvas с рамками и зонами. Снапшоты и стоп-кадры рисуются этой же сценой, а клип показывается как реконструкция по кадрам.

### Адрес API

- По умолчанию запросы идут на тот же origin. В проде их принимает FastAPI, в dev — прокси Vite.
- Цель прокси в dev задаётся так: `GUARD_API_URL=http://10.0.0.5:8000 npm run dev`. Переменную можно положить и в `frontend/.env.local`.
- Если UI и API на разных хостах, адрес API вшивается в сборку: `VITE_API_BASE=http://10.0.0.5:8000 npm run build`. WebSocket-адрес строится из него (`http` → `ws`). На бэкенде тогда нужен CORS.

### Потоки MJPEG и лимит соединений

Браузер держит не больше 6 HTTP/1.1-соединений на один origin, а каждый `stream.mjpg` занимает одно соединение, пока открыт. Поэтому живой MJPEG показывается максимум для `VITE_MAX_MJPEG` камер (по умолчанию 4). Первыми его получают камеры с активным нарушением. Остальные плитки раз в секунду опрашивают `frame.jpg` и помечены «кадр / 1 с». Если вынести стримы на отдельный порт или хост бэкенда либо включить HTTP/2, лимит можно поднять.

### Раздача из FastAPI

Ассеты собираются с относительными путями (`base: './'`), а маршрутизация — через hash (`/#/journal`). Поэтому достаточно `app.mount("/", StaticFiles(directory="frontend/dist", html=True))`, SPA-fallback не нужен. Mount на `/` подключается после роутов `/api` и `/ws`.

## Экраны

| Путь | Экран | Для кого |
|---|---|---|
| `#/` | **Мониторинг**: сетка камер (MJPEG `stream.mjpg`, бейджи FPS и p95), подсветка камеры с активным нарушением, лента тревог (критические закреплены сверху, со звуком), счётчик неразобранных, хроника смены | диспетчер, мастер |
| `?event=<id>` | **Карточка события** — модальное окно поверх любого экрана, ссылку можно переслать. Кадр с рамкой, клип ±5 с, камера, участок, зона, время, задержка оповещения по этапам. Решение: `1` подтверждено, `2` ложное, `3` передано мастеру, `C` комментарий, `N` следующее неразобранное, `Esc` закрыть | диспетчер |
| `#/journal` | **Журнал**: фильтры по периоду, типу, камере, зоне, статусу и важности (сохраняются в адресе), пагинация, превью кадров, экспорт CSV для Excel (`;`, UTF-8 BOM) по всем страницам выдачи | служба ОТ, юристы |
| `#/analytics` | **Аналитика**: по типам, участкам и камерам, тепловая карта «день недели × час», по дням, решения оператора и доля ложных по каждому правилу. У каждого графика есть табличный вид | менеджмент |
| `#/cameras/:id` | **Камеры и правила**: CRUD камер; редактор зон на стоп-кадре (рисование мышью, перетаскивание вершин, расписание активности); правила с формой из `params_schema`; сохранение через `PUT /api/cameras/{id}` | специалист ОТ |
| `#/performance` | **Производительность**: активный бэкенд и загрузка ускорителя, FPS по камерам и во времени, задержка по этапам p50/p95 (stacked bar), таблицы потоков и моделей | ИТ-служба |

Звук критической тревоги синтезируется через WebAudio, аудиофайлы не нужны. Браузер разрешает звук только после первого клика на странице. Переключатель звука находится в верхней панели. Баннер критической тревоги виден на любом экране.

## Структура

```
src/
  api/            http.ts (fetch + ошибки FastAPI), ws.ts (переподключение с backoff),
                  queries.ts (TanStack Query), mock/ (данные, сцена canvas, фейковый WS)
  domain/         types.ts (зеркало guard/contracts.py), violations.ts (словарь типов нарушений),
                  labels.ts, format.ts, zones.ts, period.ts
  state/          live.ts (лента, счётчики, метрики из WS), LiveConnector.tsx, settings.ts
  components/     layout/ (каркас, баннер тревоги), media/, charts/, ui/
  features/       monitoring/, event/, journal/, analytics/, cameras/, performance/
scripts/          screenshots.mjs (Playwright), shoot.sh (dev-мок → скриншоты → стоп)
```

Новый тип нарушения из плагина (R7) показывается без правки UI: название берётся из `/api/rules/types`, форма параметров строится по `params_schema`. Иконку и короткое имя можно добавить в `src/domain/violations.ts`.

## Скриншоты

```bash
# тяжёлые шаги — только через очередь памяти
../tools/heavy.sh /usr/bin/env PATH=/opt/homebrew/opt/node@20/bin:/usr/bin:/bin npm run build
../tools/heavy.sh ./scripts/shoot.sh      # поднимает vite --mode mock, снимает экраны, гасит сервер
```

Скрипт открывает один браузер с одним контекстом и снимает экраны по очереди. Результат — `data/media/ui/*.png`.
